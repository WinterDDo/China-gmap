# 出一版设计定稿

原型是一个单文件网页：`explorations/design-freeze/index.html`。每个画面是一个
`<section class="sec" id="s-…">`，用来给用户拍板，不是正式网站。开工先说一句：「我在用 design-freeze 出第 X.Y 版。」

## 第一步：读、问、定版本号

1. 先读 `docs/DESIGN.md`（只有千里江山一套风格；颜色只用设计变量；朱砂是唯一强调色）和 `docs/PRODUCT.md`（范围、治理红线、许可）。
2. 把这一轮用户的意见逐条列出来，用一句「我理解你要的是…」请他确认。文案语气、加不加某个玩法、给谁看这类问题，问清了再动手。
3. **版本号**：一轮新内容是 X.Y（如 5.7）；同一轮里的修补是 X.Y.Z（如 5.7.1「分享和下载按钮全部做成真的」）。
4. **试新方向**（如 5.8 的 3D、5.9 的电影式转场）单独成一版、单独提交，在说明里写明是「试」。用户不要时，一次撤回就能回到上一版（5.7 就是这么回来的）。撤回也算一个决定，写进 `STATUS.md`。

## 第二步：改原型

- **新画面**照现有区块的结构写：标题印章用壹、贰…往后排，标题和副标题挂 `data-t="键名"`，新画面带 `NEW` 标记。
- **中英同步**：固定文字放进 `T` 词典（`data-t`），动态文字用 `ZH("中文", "English")`。没有英文的文字不算写完。
- **设计语言**：颜色、字号、动效只用 `docs/DESIGN.md` 里的变量和规矩，不新造颜色。动效要能跟随系统设置减弱。
- **数据诚实**：
  - 真实数字要能点开看出处。
  - 示意内容标「示意」，虚构的人名和数字在页脚声明。
  - 缺失显示「—」或「采集中」，绝不显示 0。
  - 原型数据（`data/*.json`）由同目录的 `design_prep.py`、`enrich_life.py`、`build_flows.py`、`build_search.py` 生成，优先重新生成。输入不在手边、只能手改时，在提交说明里写清改了哪条、依据哪句原文。
  - 改完跑一次 `python3 -m pipeline check`，确认原型数据没有违反数据铁律。
- **红线**：治理只讲历史，不收录现任官员；未获许可的历史数据不上；页脚保留「本原型仅供设计确认，未申请审图号」。

## 第三步：打分，改到达标

原型里自带两张评分表：
- **手机**：`RUBRIC`（A 一看就会用、B 主次有序、C 探索不卡壳、D 留得住会回来、E 手机好用，满分 100）加 `BASICS`（P0、P1 基础功能清单），分数记录在 `SCORE` 里。
- **桌面**：逐页评分，用同一套 A 到 E。

规矩：
- P0 没有全部打勾，总分封顶 90。目标是每一页都在 95 分以上。
- 每一轮：先截图，再照着截图打分，不凭记忆打；然后找最低的一项去改，改完再截图、再打分。新一轮记进 `SCORE.history`。
- 每一分都要指得出依据（哪张截图、哪个画面）。没有改动就不加分。

## 第四步：自查（测试绿不等于做完）

在仓库根目录跑：

```bash
node tools/shots.js s-mobile s-phone <这一版改过的区块…>
```

- 每个改过的区块都看四张图：手机和桌面、中文和 EN。重点看文字溢出、中英混排、空状态、颜色是不是来自设计变量。
- 页面报错不为 0，先修好再往下走。
- 动过按钮、链接或弹层，再跑一次按钮审查。它会逐个点遍每个区块的按钮，列出「点了没反应」的。全部区块约 5 分钟；只审改过的区块，在命令前加 `SECS=s-duel,s-archive`，一个区块约半分钟：

  ```bash
  (cd explorations/design-freeze && python3 -m http.server 8790 >/dev/null 2>&1 &) && sleep 1 && node explorations/design-freeze/audit-buttons.js http://127.0.0.1:8790/index.html; pkill -f "http.server 8790"
  ```

  地址要写到 `index.html`：页面没有声明编码，只写到目录时浏览器会把中文认成乱码，结果不可信。
  `dead:` 后面应该是空列表 `[]`（真人点得到、点了没反应）；`covered:` 是被别的东西挡住、真人此刻点不到的，看一眼是不是本来就该被挡住（比如开局浮层）。报出来的按钮先确认是真坏：审查看的是页面文字、地址、提示条、滚动和地图画面有没有变，回到起点类的按钮（如「全国」）在地图已经在全国视图时点了本来就不会变。新增的区块要加进脚本里的 `secs` 列表。

## 第五步：请用户拍板

1. 更新「请你确认」区块（`s-decide`）：只放这一轮只有用户能答的问题，比如口味、文案语气、先做哪个。每个问题给两三个选项，写上我的推荐。上一轮已经答过的删掉。
2. 给用户看**对照图**（`shots/<区块>-sheet.png`），默认用中文界面，不给链接。说清这一版他能看到哪些变化，用他的话说，不说代码。
3. 用户说可以之前，这一版在 `STATUS.md` 里留在「还没验证」。他拍板的口味决定写进「已做的决定」，同一个问题以后不再问。

## 第六步：提交

- 提交信息：`Design freeze X.Y: <用户看得到的变化>`。只是修补用 X.Y.Z；撤回一个尝试写 `Back to design freeze X.Y: …`。
- 每次提交都会自动跑全部测试，不全绿就提交不了。
- `STATUS.md`：在「最近的变化」里加一行，在「还没验证」里写上「等你看过对照图」。
