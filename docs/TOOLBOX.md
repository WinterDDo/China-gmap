# 开发工具箱：skill 与 harness

让 Claude 开发得更快、更不容易出错的那些东西：每样是什么、帮你什么、怎么用。
进度和候选项在 `STATUS.md`；规则本身在 `CLAUDE.md`。

## 自动生效的（不用记得去做）

| 工具 | 帮你什么 | 在哪 |
|---|---|---|
| 你的沟通规则（i-dont-read-code） | 每轮提醒：报结果不报过程，坏消息先说，每个「做完了」都带验证标签 | `.claude/skills/i-dont-read-code/` |
| 操作记录 | 自动记下实际跑过什么；说「我看过」时必须拿得出对应记录 | 同上，记录在 `.i-dont-read-code/`（不进仓库） |
| 开工读进度 | 每次新会话先读 `STATUS.md`；放了 7 天以上的「等你做的」会被提出来 | 同上 |
| 文件来历提示 | 每个会话第一次打开某个文件时，自动列出它最近几次修改和相关的已做决定，改之前先知道以前为什么这样 | `.claude/hooks/file-history.py` |
| 决定总账 | 每个决定的原因、放弃了什么、谁定的、出处；几个会话同时追加也不冲突 | `docs/DECISIONS.md`，格式由 `tests/test_decisions.py` 检查 |
| 本项目每轮提醒卡 | 8 条：数据铁律、红线、截图规矩 | `.claude/project-card.sh` |
| 提交和推送前跑测试 | 每次提交、推送前自动跑全部测试（约 5 秒），不全绿就提交、推送不了；推送也拦，是因为合并别的会话的分支后，各自绿的两边合起来可能是红的 | `.claude/hooks/test-before-commit.py` |
| 协作看板 | 开工时自动列出：别的会话在改哪些文件、和你撞没撞、主线有没有新提交、哪些分支很久没并进来、下一个设计定稿版本号 | `tools/board.py`，规则见 `docs/COLLABORATION.md` |
| 守卫测试 | 下面这些一旦失效，测试就变红：看板认不出撞文件或遗留分支、提醒卡没接上、过期提醒失灵、规则文件和提醒卡超出篇幅（只降不升）、进度文件超出开工时能读到的长度、skill 提到的文件或代码不存在了 | `tests/test_claude_setup.py` |
| 数据铁律检查 | 每个数字要有原句，原句里真有这个数；缺失不写 0；不拿别的年份补。采集结果和原型的全部城市都查 | `pipeline/check.py`，`tests/test_data_rules.py` |

## 要用时调出来的

| 工具 | 什么时候用 | 怎么用 |
|---|---|---|
| 一键截图 | 改了界面，要自己看或请你拍板 | `node tools/shots.js [区块…]`：手机和桌面、中文和 EN 四张图，加一张对照图，一个区块约 25 秒 |
| 按钮审查 | 动过按钮、链接、弹层 | 见 `design-freeze` skill 第四步：全部区块约 5 分钟，只审改过的区块约半分钟一块 |
| skill `add-data-source` | 接一个新数据源 | 先问口径和许可，照现有数据源的结构写，最后检查加抽查原文 |
| skill `design-freeze` | 出一版设计定稿 | 中英同步，按评分表改到 95 分以上，截图和按钮审查自查，请你拍板 |

## 新会话怎么接上前面的来龙去脉

新会话什么都不记得，能接上全靠下面四层。越往上越自动，越往下越全：

1. **开工就知道**（自动）：规则（`CLAUDE.md`）、进度和等用户做的事（`STATUS.md`）、别的会话在改什么（看板）。
2. **改到哪个文件，就知道它的来历**（自动）：文件来历提示列出最近的修改和相关决定。
3. **要查就查得到**：`docs/DECISIONS.md`（为什么、放弃了什么、谁定的）；提交的完整说明（`git show <编号>`）；
   提交末尾的会话链接，能读回当时和用户的对话。原因找不到时按这个顺序查，不凭印象下结论。
4. **收工要留下**：做到哪写进 `STATUS.md`；拍板和放弃的写进 `docs/DECISIONS.md`；改了什么、为什么写进提交说明。
   前三层都靠这一层喂。漏写的代价，是下一个会话重新问用户一遍，或者把推翻过的方案又做一遍。

## 加一样新工具之前

先按 `CLAUDE.md`「一条新规则该放哪」分流：机器能查的写成测试或钩子；每轮都要提醒的才进提醒卡；用到才查的写进 `docs/`。加了新工具，把它补进这份清单。
